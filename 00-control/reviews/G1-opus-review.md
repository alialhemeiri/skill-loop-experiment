# G1 findings — most severe first

### BLOCKER 1 — `01-fixtures/generator/generate.py:332-427` (`_critical_lines` / `_layout_header`) — the task has zero headroom: v0 already scores 100%
Every gold value is rendered on a line whose label is the field name in English (`Unit number: E-0205`, `Community: Al Nakheel Gardens`, `Renewal notice period: 60 calendar days`, `Early-termination penalty: 1 month of the agreed rent`, `Furnished status: semi-furnished`). Distractors live in unrelated later paragraphs and never sit next to a matching label. **Measured this session:** v0 run once against all 10 training docs through the exact frozen invocation, fences stripped offline before grading → **120/120 fields correct, mean field accuracy 1.0000, 0 hallucinated-absent, 0 errors of any kind.** This makes H1 ("the loop's final skill beats v0 on the held-out set") unfalsifiable on extraction quality — there is nothing left to improve, so no patcher diff can raise the true signal, and every iteration will be noise-driven. *Fix direction:* raise task difficulty before freezing — unlabeled/indirect renderings, values only derivable from prose, distractors that sit under a matching label (e.g. an agent's name beside "Landlord's agent", a chiller deposit beside "deposit"), and at least one field per doc requiring inference rather than copy.

### BLOCKER 2 — `04-runner/run.py:24-33` + `02-evaluator/grader.py:213-225` + `03-skill/versions/v0/SKILL.md:21-36` — ~83% of runs are code-fenced and score 0, so the metric measures markdown fences, not extraction
The frozen grader parses strictly (no fence stripping, correctly per SPEC §5), and the worker wraps its JSON in ` ```json ` despite both the FIXED SCHEMA INSTRUCTION ("no markdown fences") and v0's own rule ("no markdown or commentary"). **Measured: 29/35 v0-verbatim runs fenced (82.9%, Wilson 95% CI ≈ 67–92%)**, across 5 independent blocks and 10 distinct documents, using a byte-exact replication of `run.py`'s subprocess call (`load_worker` → `build_prompt` → same args, same empty cwd; `transport_failure_reason` returned `None` and `num_turns=1` on every call). Consequences: v0's *as-graded* score is ≈ 0.17, not 1.0; the per-20-run SD is √(0.83·0.17/20) ≈ **8.4 percentage points**, so SPEC §7's `max(1 SD, 1.5pp)` threshold lands at ~8.4pp; and the single largest score movement available to the loop (0 → ~1.0) is "stop emitting a code fence". Combined with BLOCKER 1, the experiment as frozen measures exactly one binary behaviour. I also probed whether v0's own ` ```json ` block is the cause — removing it gave 2/3 unfenced vs 1/3 unfenced for the control, i.e. not obviously fixable from inside the skill. *Fix direction:* decide and pre-register one of — (a) harden the frozen harness instruction/system prompt until the bare-JSON rate is ~100% so the metric is about extraction, or (b) register a single fence-strip in the runner before writing `preds/`, keeping "unparseable after strip = 0", and log it as a methods fact.

### MAJOR 3 — `PLAN.md:62-65`, `PLAN.md:145-152` — the P2 dry-run all-clear is a ~3% fluke and its causal story is wrong
`05-runs/p2-dry` (2/2 clean, mean 1.0) is recorded as the acceptance evidence, and the earlier fenced batch is described as pre-hardening. With p(unfenced) ≈ 0.17, two clean runs in a row is a ≈2.9% event; the "runner hardening removed the fences" inference is unsupported — the current runner reproduces fences at 83%, and the `p2-dry` manifest's `skill.sha256`, `system_prompt.sha256`, `fixed_schema_sha256`, `runner.sha256` and both document hashes all still match the files I probed with. The existing G1 watch-item ("v0 hit 1.0 on both dry docs — ceiling risk; noise floor will show real headroom") is correct but was never measured; it is now measured and the ceiling is real. *Fix direction:* correct the session log before it feeds the article's methods section, and treat n=2 dry runs as insufficient acceptance evidence for any future gate.

### MAJOR 4 — `00-control/worker.json:6-7,14` — the model pin is an alias, not a snapshot, and nothing records the resolved version
SPEC §6 requires "exact model string pinned at G1". `claude-sonnet-5` is an alias; the CLI result envelope reports the same alias back in `modelUsage`, so no artifact captures which snapshot served any run. Across ~630 runs spread over multiple nights, a mid-experiment model change would silently confound the v0 noise floor against the held-out run, and FREEZE.md's hashes cannot detect it. *Fix direction:* pin a dated snapshot id if the CLI exposes one; if not, register the alias limitation explicitly, record the resolved model per run in the manifest, and re-measure the v0 noise floor immediately before the held-out run as a drift check.

### MAJOR 5 — `04-runner/run.py:518` (`max_attempts_per_run = 1 if holdout_mode`) — holdout transport failures are unrecoverable and contradict the registered transport rule
worker.json's `transport_retry_rule` is registered as "retry max 2 … ONLY on transport failure … a model failure is never retried". The runner overrides it for holdout, reading SPEC §7's "no retries" as covering transport too. One nonzero exit or empty stdout on a holdout run then yields no prediction file, which the grader scores 0/12 — **8.3 percentage points of a 6-document mean**, decided by a network blip rather than the skill. Resuming the same `--batch-id` refuses to re-run it (`heldout_no_reroll_resumes`), so there is no legitimate recovery path; the only escape is a new batch-id, which defeats the single-shot guarantee. *Fix direction:* pre-register the tie-break explicitly at G1 — SPEC §7's "no retries, no re-rolls" governs *model outputs*, worker.json governs *transport* — and let holdout retry transport failures under the same logged budget.

### MAJOR 6 — `04-runner/run.py:341-345, 384` — "held-out, touched exactly once" is enforced per batch-id, not globally
`--allow-holdout` plus any fresh `--batch-id` re-runs the holdout set from scratch with no record that it was already consumed. The re-roll guard only protects runs inside one batch directory. SPEC §7.5 and G2 rest entirely on this property. *Fix direction:* a one-line append-only ledger (e.g. `00-control/holdout-usage.log`) that the runner writes to and refuses a second holdout batch against, or at minimum record it as an operator-discipline caveat in FREEZE.md.

### MAJOR 7 — `01-fixtures/gold/doc-01.json … doc-16.json` — train and holdout have materially different null rates on exactly the axis the loop optimizes
Nullable-field slots that are null: **train 18/40 (45%), holdout 16/24 (67%)**. Per field, `furnished_status` is null in 3/10 train docs (30%) but 5/6 holdout docs (83%); `security_deposit_aed` 50% vs 67%; `early_termination_penalty_months` 50% vs 67%. A blind "always null" strategy earns 0.150 of mean field accuracy on train but **0.222 on holdout**. Any null-leaning drift the loop picks up is differentially rewarded on the held-out set, so a holdout win is confounded with a distribution artifact rather than generalization. *Fix direction:* re-seed or index-swap the split so per-field null rates match within a few points, and record the resulting rates in FREEZE.md.

### MAJOR 8 — `00-control/SPEC.md:103-113` (§7.1 vs §7.5) — the keep/revert threshold is calibrated on 10-doc variance but applied to a 6-doc holdout comparison
The noise floor is 4 × (10 docs × 2 reps); H1's decision uses the same threshold against 6 docs × 2 reps, whose standard error is ~√(10/6) ≈ **1.29× larger**. G1 is the gate where the threshold is frozen, so this is the moment to fix it. *Fix direction:* register either a separately measured holdout noise floor for v0, or an explicit √(n_train/n_holdout) scaling of the frozen threshold for the H1 test.

### MAJOR 9 — `02-evaluator/grader.py:249-290` — SPEC §5's score has no implementation and will not be in FREEZE.md
"Score of a candidate = mean field accuracy over 10 training docs × 2 reps (20 runs)" is the experiment's central quantity, but `grade_directories` takes one `--pred-dir`, so a 2-rep evaluation needs two invocations plus an aggregation step that does not exist, is untested, and is not on SPEC §8's hash list. The aggregation happens to be unambiguous here (equal docs per rep), but it will be written post-freeze, outside the frozen set. *Fix direction:* add a thin `--reps-root` aggregate mode (or a separate frozen `score.py`) with a test, and include it in FREEZE.md.

### MAJOR 10 — `02-evaluator/grader.py:220-225, 264` — a missing prediction file is silently reported as `unparseable`
`_load_prediction` catches `OSError` alongside `JSONDecodeError`, so "the runner never produced this run" and "the model emitted non-JSON" are the same number. SPEC §5 tracks unparseable specifically as a model failure. A transport-lost run therefore inflates the model-failure count and depresses the candidate's score with no signal that infrastructure was at fault (`test_batch_missing_prediction_file_is_zero_and_unparseable` locks this behaviour in). *Fix direction:* add a distinct `missing` counter, and require a manifest-completeness assertion (all runs terminal, zero transport failures) before any score is recorded.

### MAJOR 11 — `04-runner/run.py:732-799` — the worker keeps its tool scaffolding and nothing checks `num_turns == 1` at runtime
worker.json's isolation evidence covers dynamic system-prompt sections (CLAUDE.md, memory, env) but explicitly notes "residual = fixed Claude Code tool-schema scaffolding". The worker therefore still has file tools; only the empty cwd stands between it and `01-fixtures/gold/`. `num_turns` is asserted once in `04-runner/test_run.py:273` against a mock, never against a real run, and the runner never inspects it or `permission_denials`. The channel is *detectable* post-hoc from the stored envelopes but is neither blocked nor checked. All 4 stored dry-run envelopes plus all 35 of my probes show `num_turns=1` and empty `permission_denials`, so nothing has leaked — but that is luck, not a guarantee. *Fix direction:* add a tool restriction to the pinned args if the CLI supports one, and have the runner fail the run loudly on `num_turns != 1` or non-empty `permission_denials`.

### MINOR 12 — `02-evaluator/grader.py:189-206` — no false-null counter to pair with `hallucinated_absent`
The score itself is symmetric (a missed present value and a hallucinated absent value each cost 1/12), but only one direction is counted and reported. SPEC §2 lists "hallucinated-field rate" as a secondary metric, so a null-spamming drift would show as an *improving* secondary metric while extraction got worse. It is derivable from stored outputs, but not before the loop's keep/revert decisions are made. *Fix direction:* add a `missed_present` counter now (post-freeze it is an amendment plus a full re-score).

### MINOR 13 — `02-evaluator/grader.py:185, 190` — valid JSON that is not an object scores 0 but is counted nowhere
A top-level array or scalar yields `unparseable: False`, `hallucinated_absent: 0`, `score: 0.0`. SPEC §5 promises zero-score runs are "tracked separately"; this class is invisible in the report. Locked in by `test_parseable_nonobject_scores_zero_but_is_not_unparseable`. *Fix direction:* a `wrong_shape` counter alongside `unparseable`.

### MINOR 14 — `02-evaluator/grader.py:139-144` — `furnished_status` skips the whitespace/punctuation normalization SPEC §5 registers for strings
SPEC §5 says "strings casefolded, whitespace collapsed, honorifics and role suffixes stripped"; the P1 contract narrowed this field to "casefolded" only, so `" furnished "` is graded incorrect (`test_furnished_status_rejects_extra_formatting`). Low-probability, but it is a correct extraction scored wrong. *Fix direction:* apply `" ".join(value.split())` before the enum lookup, or record the narrowing as a registered deviation.

### MINOR 15 — `01-fixtures/generator/generate.py:267` — `strftime('%B')` is locale-dependent
The "long" date style renders month names through the C library's `LC_TIME`. CPython does not call `setlocale` at startup, so this box always yields English, and I could not trigger a divergence (only `C`/`C.utf8`/`POSIX` are installed here) — but any host process that has called `setlocale(LC_TIME, "")` would silently produce different fixture bytes, breaking the byte-reproducibility guarantee that the whole freeze rests on. The determinism test (`test_same_seed_is_byte_identical`) runs both generations in one process and cannot catch it. *Fix direction:* replace with a hardcoded month-name tuple.

### MINOR 16 — `02-evaluator/grader.py:66-67` — `unicodedata.category` makes punctuation stripping Unicode-version dependent
Only affects non-ASCII characters outside `string.punctuation`, so it will not bite on this corpus, but it is a cross-Python-version nondeterminism in a file that must be re-runnable years later. *Fix direction:* an explicit character set, or accept and note it.

## Verdict

**Do not freeze.** The build quality is high — the runner is the most careful piece of work here (fail-closed resume, cumulative retry budgets, six distinct corruption refusals, byte-exact raw storage, complete hash manifest), the grader implements SPEC §5 faithfully and deterministically, the generator is byte-reproducible and passes `--check`, and 100 tests pass. But the test bed measures the wrong thing. Two independent and mutually reinforcing defects make the frozen metric uninformative about the hypothesis: v0 already extracts **120/120 fields perfectly** across the whole training set (no headroom — H1 cannot be won on extraction), while **83% of runs are scored 0 purely because the model wraps its JSON in a markdown fence** (a ~8.4pp-SD coin-flip that swamps everything else and is the only quantity the loop can actually move). If frozen as-is, the experiment would spend ~630 worker runs and produce a score trajectory whose entire signal is fence suppression, and the article's central claim — a controller pattern improving a real task against a frozen score — would rest on an artifact. Both defects are cheap to fix now and expensive after G1: raising fixture difficulty is a fixture change (voids results under §9), and fence handling is either a harness or a grader change (amendment plus full re-score). The remaining MAJORs — alias model pin, holdout transport irrecoverability, ungoverned holdout re-use, the 45%-vs-67% train/holdout null shift, and the unscaled threshold — are all G1-gate decisions that must be settled in the same pass. Recommend a P3 remediation round, then re-review, then freeze.

## Lens-by-lens

1. **SPEC conformance** — findings 3, 5, 8, 9, 14, 21, 23. The registered artifacts match SPEC §3–§7 closely; the deviations are the holdout retry override (5), the missing score implementation (9), the `furnished_status` normalization narrowing (14), and the not-really-seeded typos (23).
2. **Determinism** — findings 15, 16. Generator: no clock, no set iteration, no unseeded randomness, single `random.Random` instance, explicit `newline="\n"`, `--check` byte-clean, `f"{v:,}"` is locale-independent; the one real hazard is `strftime('%B')`. Grader: fully deterministic apart from the Unicode-version dependence in `_is_punctuation`.
3. **Grader fairness + tightness** — findings 12, 13, 14, plus 10. Checked against the actual renderings: `CAMILA DUARTE` (casefold ✓), `Mr./Mrs. X` (honorific regex ✓), `X (the Tenant)` (role suffix ✓, and the combined `"Mr. X (the landlord)."` case is ordered correctly), `Dhs. 174,000/-` and `One hundred thirty-eight thousand dirhams (AED 138,000)` (integers ✓), Arabic labels (never enter a gold value ✓), `A-1207` unit numbers (internal hyphen preserved ✓). No path found by which a correct extraction is scored wrong except finding 14, and none by which a wrong extraction is scored right.
4. **Leakage channels** — finding 11, plus 19. Prompt construction is clean: `build_prompt` sends skill + one document + the fixed instruction and nothing else; cwd is an empty neutral directory whose emptiness is enforced at startup; no gold, scores, or sibling documents ever reach the worker. v0's content shows no fixture reverse-engineering — it covers payment phrasings the generator never emits ("semi-annual", "twice-yearly"), week/month notice conversions that never appear, and a nullable `community` that does not exist; the one fixture-specific literal is doc-01's date (19), which was a permitted input. Holdout is guarded (`run.py:341-345`, tested both ways) but only per batch-id (6).
5. **Metric-gaming surfaces** — findings 2, 7, 12. Fence suppression is the dominant surface and is *unblocked and unmeasured as such* (2). Null-spamming is bounded (0.150 train / 0.222 holdout of mean field accuracy) and half-measurable via `hallucinated_absent`, but the reverse error has no counter (12) and the train/holdout null shift amplifies it (7). Schema-echo of v0's all-null template earns only the gold-null fields, ~0.15 — an accepted risk worth logging. Normalization looseness: none found exploitable.
6. **v0 sanity** — clean, with notes 19 and 20. 96 lines / 5,297 bytes (within 150 / 10 KB), plain practitioner instructions, no deliberate flaws, no fixture reverse-engineering, and demonstrably not sandbagged — it extracts perfectly whenever it emits bare JSON. If anything it is *too* good for the fixtures, which is finding 1's problem, not v0's.
7. **Test-suite adequacy** — finding 24. No vacuous tests found; every grader rule I could identify has both a positive and a negative case.
8. **Runner robustness** — findings 5, 6, 10, 11, 22. Resumability is correct and fail-closed (a failed or missing-artifact run cannot be silently skipped or re-rolled; `test_missing_completed_artifacts_abort_instead_of_rerolling` and `test_terminal_transport_failure_is_not_given_a_new_budget_on_resume` both hold). The transport-vs-model rule is implemented exactly as registered for training batches and deliberately overridden for holdout (5).
